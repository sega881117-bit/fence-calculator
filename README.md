# Статический калькулятор для GitHub Pages

Этот каталог можно разместить на GitHub Pages: он считает смету и открывает системный диалог печати/PDF без n8n.

## Что работает без backend

- расчёт по утверждённым ценам из `prices.json`;
- несколько строк забора в одной смете;
- дефолты: профлист односторонний, высота 2 м, распашные ворота 4 м, калитка рядом;
- явные цены `по 2250`, `калитка по 15к`, доставка и удлинение столбов;
- кнопка «Открыть PDF» через печать браузера.

## Подключение единого прайса

Таблица «Цены для Авито» закрыта от публичного чтения — это правильно. GitHub Pages не должен получать к ней прямой доступ. Путь такой:

1. Развернуть `../draft-proxy-site` как Cloudflare Worker.
2. Создать сервисный аккаунт Google, дать его email доступ **только на чтение** к таблице «Цены для Авито».
3. В Worker Secrets записать `GOOGLE_SERVICE_ACCOUNT_EMAIL` и `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY`; в Variables — `PRICE_SHEET_ID`, `PRICE_SHEET_RANGE=Цены!A5:F40`, `ALLOWED_ORIGINS`.
4. В `config.js` вписать URL `/v1/prices` опубликованного Worker.

Worker возвращает только цены. Ключ Google, amoCRM и любые токены в GitHub Pages не попадают.

Рабочий адрес API уже задан в `config.js`. `prices.json` остаётся только контрольной копией для автономной проверки.

## Публикация GitHub Pages

1. Создать репозиторий GitHub и загрузить содержимое этого каталога в ветку `main`.
2. В GitHub: **Settings → Pages → Deploy from a branch → main / (root)**.
3. Полученный HTTPS-адрес использовать как страницу ручного калькулятора.

## Что требует отдельного backend

Кнопка «Добавить PDF в сделку amoCRM» не может безопасно работать в GitHub Pages: для неё нужен Cloudflare Worker или другой backend с OAuth amoCRM. Секреты amoCRM и Google не помещаются в GitHub Pages и не хранятся в браузере.

После публикации эту статическую страницу можно подключить как внешний интерфейс, а текущий пакет amoCRM переключить на тот же backend без n8n.
